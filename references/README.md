# references 索引

这个目录是 `SKILL.md` 的展开层：`SKILL.md` 写流程与判据，这里写每一步的具体打法。

**按需读取，不要一次全读。** 每个文件对应流程中的一步，用到哪一步再打开哪一个。

| 文件 | 什么时候读 | 核心产出 |
|---|---|---|
| `research-playbook.md` | Step 2 公司与岗位研究 | 公司速览 + 数字表 + 岗位 5 个真实场景 + 岗位要面对的文件清单 + 可能的追问与答法 |
| `question-bank.md` | Step 3 形式判定 / Step 4 题库准备 | 8 种面试形式对照表、结构化追问树、群面七块打法、反问工具箱 |
| `answer-format.md` | Step 6 答案三段式 | 每题的锚点词 + 表述池、思考逻辑链、可直接念出口的逐字稿 |
| `deliverable-html-pdf.md` | Step 7 交付 HTML + A4 PDF | 构建管线（build → measure → converge）、视觉与结构规范、五个静默坑 |
| `debrief-compare.md` | Step 8 多岗位对比与面试复盘 | 岗位对比表、逐题判分表、硬失分点清单、亮点清单 |

## 你现在卡在哪，就打开哪一份

| 你现在的状态 | 打开 |
|---|---|
| 还说不清这家公司做什么 | `research-playbook.md` |
| 不知道这轮是群面还是结构化 | `question-bank.md` 的「形式对照表」 |
| 题有了，答案写出来像流水账 | `answer-format.md` |
| 答案写好了，交付成一堆没人看的文档 | `deliverable-html-pdf.md` |
| 面完了，想知道到底差在哪 | `debrief-compare.md` |

## 一条贯穿全部 reference 的纪律

**数字必须带来源与期数；推演必须标「情景推演」；检索不到就写「公开信息未披露」。**

宁可少给一个数字，不给错一个——口径错一个字，面试现场追问答不上，整场就崩在那一处。
