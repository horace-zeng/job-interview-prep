# 研究与查证手册（公司与岗位）

目标：让用户能说清"这个岗位每天在干什么、我为什么正好是它的人"，且每个数字都站得住。

## 一 · 公司研究

### 查什么

| 维度 | 抓什么 | 为什么 |
|---|---|---|
| 业务结构 | 分部收入构成、在手合约额/订单储备、区域分布 | 面试官问"怎么看我们公司"，答的是业务结构不是行业套话 |
| 财务健康度 | 营收/净利/毛利率趋势、负债率、现金流 | 面试官会拿公司近况反问你的判断 |
| 竞争位置 | 主要对手是谁、市场份额、优势来源 | 能说出"我们赢在哪"比背公司介绍有用 |
| 战略动向 | 近一年新业务、并购、出海、转型 | 用户应聘的是"接下来三年"的那个公司，不是历史 |
| 风险 | 出险/债务/评级/政策暴露 | 主动说风险比被问出来强 |

### 来源纪律

- 年报/中报/招股书的数字要带**期数与口径**："2025 年在手合约额 5,564.2 亿港元"，
  不要写"公司在手合约五千多亿"——口径错一个字，追问就崩
- 二手媒体只用于补背景，且要标"据 XX 报道"
- **同一指标多个来源冲突时**：两个口径都写出来，但**必须同时给一个"面试用口径"**，
  并说明依据（通常时间更新者优先，如最新校招公告 > 更早的宣传稿）。
  只并列不给结论 = 把选择成本推给用户，用户带着两个数字上考场比带错一个更糟
- 检索不到就写"公开信息未披露"，不要估算后当事实用

### 输出形态

一段"公司速览"（读者 30 秒能读完）+ 一个数字表（供面试直接引用）+ 一段
"可能的追问与答法"。数字表要能被直接抄进逐字稿。

## 二 · 岗位研究

### 拆岗位的六个问题

1. **职级序列**：这是初级/中级/资深？招聘的是通才还是专才？有没有带人？
2. **汇报对象**：向谁汇报，说明这个岗位的话语权边界
3. **考核 KPI**：拿什么打分（签约额 / IRR / 回款 / 项目交付）——这决定用户该强调什么
4. **时间分配**：日常各占多少（投前筛选 / 测算尽调 / 商务谈判 / 投后跟踪）
5. **要面对的文件**：见下节
6. **隐含画像**：JD 里反复出现的词就是这个人被招的画像，逐条对照用户

### 岗位要面对的文件（必须具体到文件名）

不要写"要写报告"。要写：

- 投资可行性研究报告 / 投决材料（含哪几章、几页、给谁看）
- 尽职调查清单（法律 / 财务 / 税务 / 技术 / 商业各查什么）
- 交易文件：意向书、SPA、租约、合资协议、股东协议
- 估值模型（IRR / NPV / 敏感性分析表结构）
- 投后：月度经营报表、出租率台账、改造方案、退出材料
- 日常会议：项目周会、投委会、投后复盘

**为什么**：用户答"我看过这类文件"或"我熟悉这个流程"时，面试官追的是"哪一份、什么结构"，
具体文件名是可信度锚点。用户没接触过的，写"我知道它长什么样，因为……"，不要写"我做过"。

### 岗位日常场景（5 个真实场景）

写"每天在干什么"时用情景推演而非职责罗列。标"情景推演"。

模板：场景 N · 时间 + 触发事件 + 你的动作 + 产出物 + 协同方
例：场景 1 · 早上九点，某香港工业地块的业主找上门，诉求是卖地。
你当天要做的是：查该地块过去五年的成交记录、判断是不是重复报价、
决定约对方谈还是先做内部初筛——然后出一页初筛意见。

## 三 · 查证与推演的边界

| 内容 | 怎么标 |
|---|---|
| 年报/公告里的数字 | 写来源与期数 |
| 行业通行做法 | "一般而言" |
| 你对该公司策略的判断 | "我的理解是……这是我的判断" |
| 假想的日常工作 | "情景推演" |
| 政策/制度的硬事实 | 查原文并注明条款（如体检标准按哪一套判） |

面试里说错一个数字比少说一个数字更伤。宁可少给。

## 四 · 个人化问题的制度查证

涉及体检、身份、签证、户籍、婚育等硬条件的问题，**先查制度再下结论**，
不要凭印象说"应该没关系"。

查证顺序：官方文件原文 → 适用的是哪一套标准（通用/特殊/地方自设）→ 条款怎么写 →
在目标公司这类市场化主体上实际意味着什么。

结论通常有三层：
- **制度层**：有没有条款明确排除
- **现实层**：剩下的风险是什么（多是"前台性岗位的直觉判断"，不是制度）
- **策略层**：怎么把顾虑转成岗位问题（反问"这个岗位对外比例多少"比辩解有效）

## 五 · 检索面经的正确姿势

`web_search` 查：`公司 + 岗位 + 面试`、`公司 + 校招/社招 + 流程`、`公司 + 面经`、
`岗位 + 结构化/群面`、英文面试查 `company + interview questions`。

记录三样：**形式**（几轮、几对一、有没有群面/笔试）、**重复出现的题目**、
**时间线**（投递到面试多久、提前多久通知）。

样本少于 3 条时，明确说"公开面经样本少，以下按最常见的结构化形式准备"，
并且必须回到用户那里确认形式（见 SKILL.md Step 3）。
