# 交付：HTML + A4 PDF 手册的构建与校验

目标形态：一份可点击目录的 HTML + 同版 A4 PDF。章节多时读得动、印得下、点得准。

## 一 · 视觉与结构规范（复用已有材料时直接照搬）

同一位用户的多份备考材料应共享一套类名与版式，不要每份重造。常用类名：

```
.page.section   每节一个，id 唯一，是分页单位
.page.toc       目录页
.part-label     节标签（label-a..label-g 对应阶段色）
h2 / .deck      节标题 / 导语
h3              小节标题
.callout.callout-info / -ai / -warn   提示框 / AI 提示 / 警示
.say-box > .sl + .zh                 逐字稿框（英文标签 + 中文正文）
.mvi > .mvi-hd(.l1,.l2) + .mvi-bd     流程/时序图
table.tb                             通用表格
.hl / .muted                         高亮 / 弱化
```

结构推荐（章节多时）：**导读 → 阶段一认知 → 阶段二语言 → 阶段三材料 → 阶段四冲刺 → 附录**。
顺序按"备考推进"而不是"面试当天时序"：先知道自己要去面什么，再补语言，再攒故事，最后练开口。
附录放查阅型内容（术语详解、自测卷、群面参考）。

## 二 · 构建管线（三步，顺序固定）

```
1. build   抽 section → 重排 → 改 part-label/h2/页脚 → 解析符号化交叉引用 → 校验 → 写 HTML
2. measure 量每个 .page 节的内容高（min-height 置 0 再量）→ JSON {id, pt, pages, mh}
3. converge 渲染 PDF → 从 PDF 回读各节实际页跨度 → 回填 min-height → 再渲染（最多 5 轮）
```

**改内容后必须三步全跑**。收敛脚本只从已渲染 PDF 回读实际页跨度来更新 `pages/mh`，
它不重算 `pt`；沿用旧的 measure 结果会把旧 min-height 注入进去，目录会被撑到白占几页。

符号化交叉引用：正文里写 `{{p03a}}`、`{{RANGE:s2}}`、`{{TOTAL}}`，构建时解析成实际节号，
加章时不会串号。构建脚本要打印未解析 token 列表。

## 三 · 五个会静默出错的坑

### 坑 1 · 命名目标只对被引用的 id 生效

PDF 渲染器只为**被 `href="#id"` 引用过**的 id 建命名目标（书签 + 可点跳转）。
目录里漏掉一节 ⇒ 该节在 PDF 里点不到，也没有书签。

推论：每个 `.page` 节都必须在目录里至少出现一次 `href="#id"`。

### 坑 2 · 批量生成目录行时去重条件要"整组只让全局第一个触发"

想给 20 节做 10 行分组目录（每行两个锚点），代码写成
`if sid != GROUP[sid][0]: continue`（跳过组内非首成员）是**错的**：
每个"首成员"仍会各吐一遍整块。实测目录从 54 行静默涨到 153 行、元素高 1415pt → 4838pt，
PDF 从 118 页涨到 121 页且目录铺满 5 页。**不报错、不崩溃，只表现为页数暴涨**，排查极慢。

正确：`if sid != ALL_IDS[0]: continue`。

⇒ 改生成逻辑后先数输出行数（`html.count('<li')`）再看页数，别直接进渲染。

### 坑 3 · min-height 注入会把内容少的节撑成空白页

`.page` 的 `min-height` 按"页数 × 840pt"注入。内容变短后若沿用旧值，
该节会照占那些页，页面下半是空的。

⇒ 每次改内容后重跑 measure，别只跑 converge。

### 坑 4 · 孤页（末页只剩一两百字）的修法是压间距，不是删内容

根因是 `break-inside: avoid` 的块（`.callout` / `.say-box`）整块跳页。
实测一节 2211pt 内容占 4 页、末页仅 207 字。

有效杠杆（按优先级）：`.say-box .zh { line-height }` → `.callout { padding / margin }`
→ `table.tb td/th { padding; line-height }` → `h3 { margin }`。

⚠️ 收紧 `.callout` 的 padding 会触发回流反而**撑高**，优先动 line-height 和表格 padding。

### 坑 5 · DOM 量高 ≠ 打印页数，但打印宽度一致

`.page` 是固定宽度（210mm ≈ 793px），所以测量时不必模拟 A4 纸宽。
但 `break-inside: avoid` 会让实际页跨度大于 `ceil(内容高 / 840)`，
所以 min-height 必须用**实际跨度**回填，不能用算出来的值。

## 四 · 校验清单（交付前必跑）

用 `scripts/verify_handbook.py`：

- HTML：标签配平、id 唯一、`href="#id"` 全部有对应 id
- PDF：页数、命名目标覆盖率、每节实际页跨度与 measure 结果一致
- **无孤儿页**：任一页正文字符数 < 250 ⇒ 该页要么是空白，要么是孤页，要处理
- 目视抽查：封面、目录、每一节首页、最后一页

`scripts/measure_sections.cjs` 负责第 2 步；渲染用
`<DATA_DIR>/.builtin-skills/pdf/scripts/render_html.cjs --in x.html --out x.pdf --format A4`。

## 五 · 合并多份旧材料时的顺序

用户常有同主题的多份小册子（主手册 / 术语册 / 答册 / 校准册），要求合并成一本时：

1. 先列**章节 → 源 section 映射表**，确认没有节丢失
2. 去重：同一主题的"主册版 + 答册版"通常能并成两节互补并置，而不是二选一
3. 过期交叉引用清理（旧节号、旧册名、"见 S5"这类）→ 改成符号化引用
4. 重编目录，覆盖全部 section id
5. 按新顺序重排，并更新导读里的"本场不需要准备"的说明

保留原册不删，除非用户明确要清理——用户可能还要单独发某一册。
